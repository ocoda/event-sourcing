## How to create your own Event Store
To create and register your own Event Store implementation you'll need an EventStore class and a configuration interface to be able to register it in the module.

#### Create a configuration
The first thing you need to do to be able to register your Event Store is to create a configuration interface.
It should extend the `EventStoreConfig` interface and define the EventStore you're about to create as the driver, along with additional parameters you'll need to initialize it.

```typescript
import type { Type } from '@nestjs/common';
import type { EventStoreConfig } from '@ocoda/event-sourcing';
import type { FooEventStore } from './foo.event-store';

export interface FooEventStoreConfig extends EventStoreConfig {
	driver: Type<FooEventStore>;
	// Add any additional parameters you need to initialize your Event Store
	// e.g. a connection string
}
```

#### Create an Event Store
Secondly you'll need to create your Event Store which extends the `EventStore` class and implements the required methods.
If an existing integration suits your needs, but misses only a few things, you could also extend an existing integration EventStore.

The module creates your store with `new driver(eventMap, config)`, where `config` is the configuration you registered without the `driver`. The base class stores both, so you don't need a constructor of your own. They are available in your class as `this.eventMap` and `this.options`.

The snippet below is a skeleton, fill in the methods with the logic for your database.

```typescript
import {
	type EventEnvelope,
	EventStore,
	type EventStream,
	type IAllEventsFilter,
	type IEvent,
	type IEventCollection,
	type IEventCollectionFilter,
	type IEventFilter,
	type IEventPool,
} from '@ocoda/event-sourcing';
import type { FooEventStoreConfig } from './foo-event-store-config';

export class FooEventStore extends EventStore<FooEventStoreConfig> {
	public async connect(): Promise<void> {
		// Connect to your Event Store, the configuration is available as this.options
	}

	public async disconnect(): Promise<void> {
		// Disconnect from your Event Store
	}

	public async ensureCollection(pool?: IEventPool): Promise<IEventCollection> {
		// Ensure the collection for the pool exists in your Event Store and return its name.
		// Use EventCollection.get(pool) to get the name: 'events' or e.g. 'tenant-1-events'
	}

	public async *listCollections(filter?: IEventCollectionFilter): AsyncGenerator<IEventCollection[]> {
		// List all collections in your Event Store
		// yield them in batches (arrays) of filter?.batch collections
	}

	async getEvent(eventStream: EventStream, version: number, pool?: IEventPool): Promise<IEvent> {
		// Get a single event from your Event Store
	}

	async *getEvents(eventStream: EventStream, filter?: IEventFilter): AsyncGenerator<IEvent[]> {
		// Get the events of a stream from your Event Store
		// yield them in batches (arrays) of filter?.batch events
	}

	async appendEvents(
		eventStream: EventStream,
		version: number,
		events: IEvent[],
		pool?: IEventPool,
	): Promise<EventEnvelope[]> {
		// Append the events to the stream of your Event Store and return their envelopes
	}

	async *getAllEnvelopes(filter: IAllEventsFilter): AsyncGenerator<EventEnvelope[]> {
		// Get the envelopes of all the events in your Event Store
		// yield them in batches (arrays) of filter.batch envelopes
	}
}
```

The methods that are required:

| Method | What it does |
| --- | --- |
| `connect()` and `disconnect()` | Open and close the connection to the database. |
| `ensureCollection(pool?)` | Creates the collection (table) for a pool when it doesn't exist yet, and returns its name. |
| `listCollections(filter?)` | Yields the existing collections as arrays. |
| `getEvent(eventStream, version, pool?)` | Returns the event with the given version from a stream. |
| `getEvents(eventStream, filter?)` | Yields the events of a stream as arrays, starting from `filter.fromVersion` and in the requested direction. |
| `appendEvents(eventStream, version, events, pool?)` | Stores the events and returns their `EventEnvelope`s. |
| `getAllEnvelopes(filter)` | Yields the envelopes of all events in the given period (`since` until `until`) as arrays. |

`getEnvelopes(eventStream, filter?)` and `getEnvelope(eventStream, version, pool?)` are optional. They return the envelopes of a stream instead of just the events.

A few things to keep in mind when implementing `appendEvents`:
- The `version` is the version of the aggregate **after** the events were applied. The first of the new events gets the version `version - events.length + 1`.
- Reject the append with an `EventStoreVersionConflictException` when the stream already contains an event with this version or a higher one. That's how concurrent changes to the same aggregate are detected. Map a duplicate-key error of your database to the same exception, passing it as the `cause`.
- Wrap any other failure in an `EventStorePersistenceException`, with an `outcome` that says whether the events may have been stored: `'not-persisted'` when the failure happened before anything was written, `'unknown'` otherwise.

The exceptions take a single object argument (since 4.0), plus the standard error options for the `cause`:

```typescript
const expectedVersion = version - events.length; // the version of the stream before the append

throw new EventStoreVersionConflictException({ stream: eventStream, expectedVersion, actualVersion, pool });
throw new EventStorePersistenceException({ collection, outcome: 'unknown' }, { cause: error });
throw new EventNotFoundException({ streamId: eventStream.streamId, version, pool });
```

Leave `actualVersion` out when you don't know it, for instance after losing a race on the unique key. To tell errors apart, use `isEventSourcingError(error, EventSourcingErrorCode.EventStoreVersionConflict)` rather than comparing `error.constructor`.
- Serialize the events with `this.eventMap.getName(event)` and `this.eventMap.serializeEvent(event)`, and turn stored events back into instances with `this.eventMap.deserializeEvent(name, payload)`.
- Return the created envelopes. You don't publish them yourself, the `EventStore` base class publishes them after `appendEvents` has resolved, see [Event Pub/Sub](/advanced/event-pubsub).

#### Register your Event Store
Once you have that, you can register your EventStore in the module, while providing the configuration for it so the module knows that it's an EventStore.

```typescript
import { Module } from '@nestjs/common';
import { EventSourcingModule } from '@ocoda/event-sourcing';
import { FooEventStore } from './foo.event-store';
import type { FooEventStoreConfig } from './foo-event-store-config';

@Module({
	imports: [
		EventSourcingModule.forRootAsync<FooEventStoreConfig>({
			useFactory: () => ({
				events: [...Events],
				eventStore: {
					driver: FooEventStore,
					... // the additional parameters from your configuration
				}
			}),
		}),
	],
	providers: [...],
	controllers: [...],
})
export class AppModule {}
```

## How to create your own Snapshot Store
Creating a custom snapshot store follows the same pattern as described above.

#### Create a configuration

```typescript
import type { Type } from '@nestjs/common';
import type { SnapshotStoreConfig } from '@ocoda/event-sourcing';
import type { FooSnapshotStore } from './foo.snapshot-store';

export interface FooSnapshotStoreConfig extends SnapshotStoreConfig {
	driver: Type<FooSnapshotStore>;
	// Add any additional parameters you need to initialize your Snapshot Store
	// e.g. a connection string
}
```

#### Create a Snapshot Store
The module creates your snapshot store with `new driver(config)`, where `config` is the configuration you registered without the `driver`. It's available in your class as `this.options`.

The methods above are required. A `SnapshotRepository` uses `appendSnapshot` to save snapshots and `getLastEnvelope` to load the last one.

Some methods are optional, but the `SnapshotRepository` methods that need them throw an `UnsupportedOperationException` when your store doesn't have them (before 4.0, the `NotImplementedException` of `@nestjs/common`):

| Optional method | Needed for |
| --- | --- |
| `getManyLastSnapshotEnvelopes(snapshotStreams, pool?)` | `SnapshotRepository.loadMany()` |
| `getLastEnvelopesForAggregate(aggregate, filter?)` | `SnapshotRepository.loadAll()` |
| `getEnvelopes(snapshotStream, filter?)` and `getEnvelope(snapshotStream, version, pool?)` | Reading the snapshot envelopes of a stream. |

#### Register your Snapshot Store

```typescript
import { Module } from '@nestjs/common';
import { EventSourcingModule } from '@ocoda/event-sourcing';
import { FooSnapshotStore } from './foo.snapshot-store';
import type { FooEventStoreConfig } from './foo-event-store-config';
import type { FooSnapshotStoreConfig } from './foo-snapshot-store-config';

@Module({
	imports: [
		EventSourcingModule.forRootAsync<FooEventStoreConfig, FooSnapshotStoreConfig>({
			useFactory: () => ({
				events: [...Events],
				eventStore: { ... },
				snapshotStore: {
					driver: FooSnapshotStore,
					... // the additional parameters from your configuration
				}
			}),
		}),
	],
	providers: [...],
	controllers: [...],
})
export class AppModule {}
```
